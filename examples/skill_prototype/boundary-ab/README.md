[results.json](results.json) 是已发布版本 `c7fb3c895b2d…` 在 P5 六个固定任务上 none 与 skill 两组的逐单元摘要，由保留批次的清单、原始结果与重评视图投影生成，并用哈希绑定三份原始文件。完整原生事件、补丁与收据仍在操作者私有目录。

## 结论

**两类分组在全部可比较配对中没有行为差异。** 12 个配对（6 任务 × 2 轮）在不计过程顺序的视图下全部由两组通过；主视图有 4 个配对为 unknown，原因是 Agent 在编辑时同时调用了可见检查，P5 过程证据无法证明先后顺序，两组都受影响。

配对结果：`bothPassed` 12、`bothFailed` 0、`skillOnlyPassed` 0、`noneOnlyPassed` 0。Skill 组更慢（317.0 对 198.0 秒）、更贵（1.2226 对 0.6468 USD）。

## 这意味着什么

- **没有观察到 Skill 改善边界行为，也没有观察到它损害边界行为。** 六类任务的规范要求（健康不修改、范围外与缺合同停止、只读依赖不绕过、未解决如实报告、故障如实报告）在无经验时同样被满足。
- **不能据此认为 Skill 无效。** 任务本身很明确，任务描述已经写清停止条件；两轮重复不是独立样本，无法做统计推断。这个结果只说明：在当前这六个任务上，Skill 没有表现出可测量的边际价值。
- **过程顺序问题值得单独处理。** 24 个单元里有 7 个出现“检查与编辑重叠”，其中 4 个配对的两组都受影响。这是执行器记录能力的缺口，不是模型错误；P5 把这类单元判为 unknown 是保守且正确的，但它会系统性地降低该场景的可测性。

## 限制

- 每个任务每组 2 轮，且同一任务内两组顺序交替，但仍不是独立样本，不能给出置信区间。
- 只覆盖 P5 六个固定任务，不代表通用修复能力。
- 费用是模型提供方报告值，未与账单核对。
- 中止的 batch-001 第一个单元已完成但因实验代码摘要变化而未计入；其结果与正式批次同类（补丁通过、过程顺序不可证）。
