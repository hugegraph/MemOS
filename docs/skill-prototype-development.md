# Skill 原型开发计划与验收

日期：2026-11-08。设计依据：[Skill 提炼与演进设计](skill-extraction-design.md)。本计划先确定开发顺序、功能契约和验收，再开始实现。

## 1 本轮交付与完整原型的关系

完整原型的目标仍是“受控任务 → 实际采集 → MemOS 保存与回读 → 候选提炼 → Skill Graph → Claude Code 使用 → 独立评估 → 人工发布与演进”。按可运行增量交付，不把一次本地演示当成整个 issue 完成。

本轮实现 **P0a 离线任务与验收底座**。开发者能够创建任务副本、修改候选、运行外部验收、获取绑定快照的 JSON 回执，并检查旧回执是否仍对应当前候选。它先回答“我们能否可靠地区分正确修复、错误修复和无效验证”。

P0a 使用两个公开的 dev 合同探针，分别表达严格 Fake 签名和租户隔离机制。它们借鉴项目真实失败模式，但不是完整 DreamPersistence 或 API handler 的生产路径复现，不计作两个已采集的 Agent source 案例。真实 S1/S2、独立 holdout、Claude Code、MemOS、Neo4j 与管理页面按后续阶段交付。

## 2 为什么先做这一部分

如果没有独立验收，后续系统可能把放宽 Fake 或删除断言形成的“测试通过”提炼成经验。先建立可恢复快照、行为判定和回执绑定，可以使采集、提炼、版本和反馈共享同一套事实依据。

首增量不需要模型凭据或数据库服务，使用现有 Python 环境即可反复验证。新代码仅依赖标准库，但 `memos` 顶层包仍保留既有初始化行为；本轮不借机重构其导入机制，也不宣称能够在未安装项目依赖的解释器中直接运行。

## 5 首增量的功能契约

### 5.1 任务与对外命令

提供独立入口 `python -m memos.skill_evaluation`，不改变已有 API、公共 prompt registry 或旧 SkillMemory reader 的约束。

| 操作 | 输入 | 输出与约束 |
| --- | --- | --- |
| `list` | 无 | dev 案例 ID、revision、用途、目标；不宣称存在真实 Agent 运行 |
| `prepare` | case ID、目标目录 | 初始故障副本及任务说明；目标必须不存在，不覆盖用户已有工作 |
| `verify` | case ID、候选目录、工件目录、可选超时 | 独立执行验收，保存回执、快照及输出；区分通过、失败和验证错误 |
| `check-receipt` | 回执、当前候选、工件目录 | 检查绑定、完整性及当前代码是否仍对应回执；匹配不代表自动授予发布资格 |
| `demo` | 新的输出目录 | 对两个 dev 案例执行基线、故障、参考修复、削弱检查四种状态，形成底座自检报告 |

退出码约定：0 表示本命令的预期验证条件满足；1 表示候选未通过或旧回执不再匹配；2 表示参数、工件或验证基础设施错误。`demo` 的故障候选被拒绝是预期自检结果，不应让整个自检被误判为失败。

### 5.2 dev 合同探针

两个探针分别来自设计中的 S1/S2 机制，但使用独立的小型 Python 组件，文件内容固定、可重复物化。用途固定为 dev，不能作为 holdout 或独立经验来源导出。

| 案例 | 初始缺陷 | 正确修复 | 需要拒绝的捷径 |
| --- | --- | --- | --- |
| `dev-strict-signature` | caller 使用错误的 update_node 参数打包；Fake 严格，异常可能被吞掉 | caller 按字段映射与租户合同调用 | 放宽 Fake 接受任意参数，即使表面测试变绿也拒绝 |
| `dev-tenant-isolation` | caller 按租户查找；Fake 错误地回退到其他租户节点 | Fake 遵守租户范围，合法路径仍可写入 | 忽略租户、总是返回空或只改样例断言 |

任务可见目录只包含需要修改的代码、可见检查和任务描述。外部 oracle、参考修复和答案不随 `prepare` 导出。参考修复仅用于验收底座自检，明确记录为人工定义的 fixture，不能伪装成 Agent 经验。

### 5.3 快照

SnapshotStore 负责捕获、完整性校验与恢复。快照记录路径、文件内容、类型、可执行属性，以及受支持的符号链接目标；内容和规范化 manifest 共同确定身份。

采用独立工件目录、内容寻址和先写后固定的流程。同一状态重复捕获得到同一身份；损坏已有对象必须报错，不能静默修复后继续使用旧证明。捕获目录不能包含工件存储本身，恢复不能覆盖已有目录。

路径必须位于快照根内。对绝对链接、逃逸链接、特殊文件或其他未支持的情况明确拒绝，不静默漏采。所有被接受的普通文件包括隐藏文件，不依赖 git tracked 状态；不偷偷忽略影响行为的输入。大规模仓库与恶意并发写入的强一致快照不属于本增量。

### 5.4 外部验收与回执

验证器封存候选后，在新目录恢复只读副本，使用固定 oracle 和当前固定解释器启动独立进程。禁用字节码输出，生成物与候选分开；记录实际导入路径，确认执行的是该候选。进程超时、导入失败、缺失报告或报告结构不符记录为 error，不冒充预期反向检查通过。

验收同时检查：caller 对独立严格实现的行为、Fake 对标准调用的行为、非法调用或跨租户行为仍被拒绝，以及正常更新字段与副作用。只删除可见断言不能影响外部结果。验证前后核对候选输入不变。

回执至少绑定：schema/validator 版本、case ID/revision、用途与谱系、run/attempt ID、初始与候选快照、合同摘要、oracle 摘要、解释器与环境摘要、实际检查及标准输出/错误引用、时间和最终判定。回执固定保存，不原地覆盖。输出文件的摘要也必须可核查。

旧回执核查必须比较当前候选身份与完整的验证绑定。相同 ID 但内容、case revision、oracle 或验证器发生变化，不能复用原回执。哈希只证明记录一致性；可信验证器是执行事实的来源，不宣称仅凭哈希能证明任意第三方运行。

P0a 的普通子进程及只读文件是测试隔离手段，不是防恶意代码的安全沙箱。P1 在真实 Agent 可修改代码时，需要独立权限或容器等运行边界，保证其无法读取或修改隐藏验收与其他组工件；该能力未在 P0a 中宣称完成。

## 6 实现责任与代码布局

| 文件或目录 | 责任 |
| --- | --- |
| `src/memos/skill_evaluation/__init__.py` | 独立领域入口，不增加服务初始化 |
| `snapshots.py` | manifest、内容寻址、完整性和恢复 |
| `cases.py` | 两个 dev 任务规范、任务物化和受保护的验收材料 |
| `verifier.py` | 独立子进程、结果分类、不可变回执与绑定核查 |
| `cli.py`、`__main__.py` | 参数解析、薄命令组合、清晰退出码 |
| `tests/skill_evaluation/` | 对应失败模式、功能与 CLI 集成测试 |
| 本文档 | 阶段状态、使用方法、实际验证证据及后续边界 |

快照、案例与验证器保持独立接口，后续 Runner 复用快照和验收能力，不把模型调用、数据库和 Web 服务塞进此模块。公共接口以实际文档和测试为准，阶段一实现过程中必要的小调整同步记录。

## 7 验收矩阵

| 编号 | 验收项目 | 通过条件 |
| --- | --- | --- |
| A01 | 任务导出 | 两个 dev 案例可创建，重复目标拒绝，无 oracle 或参考解泄露 |
| A02 | 基线校验 | 合法基线与参考修复通过，更新值、目标、租户及副作用符合合同 |
| A03 | 初始故障 | 两个故障均因预期行为违约被拒绝，而非导入或语法错误 |
| A04 | 错误修复 | 放宽 Fake、忽略租户、总返回空等捷径无法通过独立检查 |
| A05 | 快照恢复 | 修改、添加、删除、隐藏文件及支持的属性可准确恢复；不依赖原目录 |
| A06 | 完整性与路径 | 损坏对象、越界路径和不支持的文件类型明确失败 |
| A07 | 实际执行对象 | 验证运行来自恢复候选，结果与不同候选行为相符 |
| A08 | 回执绑定 | 验收后修改代码、替换合同或破坏工件时，旧回执不能继续匹配 |
| A09 | 无效执行 | 超时、导入失败、异常退出和缺少结果不误报通过 |
| A10 | 分组身份 | dev fixture 与真实 source/holdout 明确区分，不产生经验数量或效果收益声明 |
| A11 | 兼容性 | 原有公共 SkillMemory 约束不变，新增模块不增加必需服务依赖 |
| A12 | 可操作性 | CLI 完整演示可重复执行，产生可读报告和明确退出码 |

## 8 验证方法与开发记录

## 9 使用与复现

在仓库根目录、已配置好的项目虚拟环境中运行。显式设置 `PYTHONPATH=src`，确保使用当前检出的代码。

列出公开 dev 案例：

```bash
PYTHONPATH=src .venv/bin/python -m memos.skill_evaluation list
```

运行完整底座自检，输出目录必须尚不存在：

```bash
skill_demo_parent=$(mktemp -d /tmp/memos-skill-p0-XXXXXX)
PYTHONPATH=src .venv/bin/python -m memos.skill_evaluation demo \
  --output "$skill_demo_parent/run"
```

`summary.json` 汇总两个案例的基线、错误、参考修复、错误修复及旧回执失效检查。`artifacts/snapshots` 保存可恢复快照，`artifacts/runs/<run_id>/<attempt_id>` 保存独立 oracle、实际输出、结构化报告和回执。输出目录可以在审阅完后整体归档或删除，不提交到 Git。

手动修改一个候选并验收：

```bash
skill_work_parent=$(mktemp -d /tmp/memos-skill-work-XXXXXX)
PYTHONPATH=src .venv/bin/python -m memos.skill_evaluation prepare \
  dev-strict-signature --workspace "$skill_work_parent/candidate"

# 阅读 candidate/TASK.md，修改允许的候选文件，再运行：
PYTHONPATH=src .venv/bin/python -m memos.skill_evaluation verify \
  dev-strict-signature --candidate "$skill_work_parent/candidate" \
  --artifacts "$skill_work_parent/artifacts" --timeout 10
```

初始错误未修复时，`verify` 预期返回 1 和 failed；正确修复返回 0 和 passed；导入、超时、缺失报告等无效验证返回 2 和 error。所有实际验证结果均保存对应回执，失败不能只从终端输出中忽略。

检查命令返回的 `receipt` 路径是否仍适用于当前代码：

```bash
PYTHONPATH=src .venv/bin/python -m memos.skill_evaluation check-receipt \
  /path/to/receipt.json --candidate "$skill_work_parent/candidate" \
  --artifacts "$skill_work_parent/artifacts"
```

`matches=true` 和退出码 0 仅表示绑定与完整性成立；同时查看 `verification_status`，原本 failed 或 error 的回执不会因此变成通过。代码或当前合同变化导致失配返回 1，回执或引用工件损坏返回 2。环境、验证器实现或 oracle 变化后需重新验证；不通过手工改回执继续使用旧结果。

既有 `memos` 包初始化可能先向标准输出写诊断日志，因此命令最终 JSON 位于最后一行，完整结果以报告文件为准。本轮保留了现有初始化行为，未为了输出纯 JSON 修改全项目启动机制。
