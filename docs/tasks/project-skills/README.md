# P3 Skill 管理与审阅界面

## P4 后续人工裁决开发范围

在固定候选详情中增加逐分支覆盖矩阵、宿主核验的待审任务材料，以及独立的人工裁决表单。任务修复、合理停止、历史异常解释与 Skill 使用分别选择；默认待补证据，需选择实际事件、填写理由和明确确认，才允许提交固定包。分支只可从宿主预先登记的候选项选择，并分别关联条件、行动和验收。没有可用证据时保持缺失，历史 unknown 不改成 passed。

manage 才能准备和提交；viewer/editor 可看事实。切项目/候选/sequence 重置旧包，409 或提交结果未知先刷新，不自动重试。新 API 与 Go/Python 同步；先测试权限、精确包、合理停止、缺证据、纠正、冲突和文本转义，再运行 `pnpm verify`，最后在可见浏览器验证真实数据。页面测试使用的裁决仅为合成数据，不代替真人审阅或发布。

入口为资源区的 **Skill 管理**，路由 `/cn/skills`。它与提示词工作台是独立功能。

## 范围与验收

本阶段页面只管理后端登记的固定候选，不能上传任意任务、路径、命令或自报通过的验证。

| 功能 | 页面行为与验收要求 |
| --- | --- |
| 发现候选 | 按当前项目读取列表，以名称/ID/标签搜索、按管理状态筛选；明确显示加载、空列表、错误状态 |
| 读取版本 | 展示完整固定 revision、管理 sequence、适用条件、排除项、约束、验收与局限 |
| 规则追溯 | 每条规则展示条件、观察、行动、结果、分支及固定来源关联；片段通过 evidence 端点读取，模型文本不执行为 Markdown/HTML |
| 隔离评测 | 只允许服务器登记的开发任务；发起一次后轮询 job，查询失败只重试查询，不重复发起任务 |
| 区分结论 | 外部任务验收、固定加载、事件采集、规则使用审阅与发布状态分别显示；`passed` job 不能自动变成已发布 |
| 固定审阅包 | 展示包摘要、内容/导出摘要、序号、来源水位、报告 ID 与逐规则分支覆盖；不足项保留服务端原因码 |
| 人工批准 | owner/平台管理员在 `PASS` 包上填写理由并明确确认；发送精确包 ID/hash、revision、sequence、operationId |
| 管理决定 | 需要理由；补证据、阻断、挑战、暂停、撤回分别调用冻结端点；服务端仍是权限与事务的最终裁定者 |
| 并发与失败 | HTTP 409 丢弃旧审阅包并要求重新读取；不自动重试批准。提交结果未知同样先重读，不盲目重放 |
| normal 准入 | 展示服务器给出的 allowed/reasons；未发布、挑战、失效依赖和范围外任务的拒绝不能被开发评测通过覆盖 |

权限未知时写按钮禁用；viewer 不可评测，editor 可以评测但不能审阅/发布。项目切换会卸载旧工作区，旧响应与审阅包不会进入新项目。

## 契约与实现位置

- `shared/contract.ts` 为传输类型唯一来源。candidate 保留 P2 规范的 snake_case；管理字段使用 camelCase。
- `src/lib/api.ts` 统一访问 11 个 `/api/v1/skills/*` POST 端点，每次显式传 projectId，不传 actor/capability。
- `src/lib/skills.contract.ts` 对列表、详情、规则证据、运行和审阅包做运行时检查。排队/未知任务允许 taskResult/skillUsage 为 null，不能把缺失结果显示为通过。
- `src/pages/Skills.tsx` 为页面，样式位于 `src/styles/console-extra.css` 的 Skill 区块。
- `openapi.json` 从 Go 控制面的 OpenAPI YAML 生成，修改契约必须与 Go/Python 协同。

## 验证方式

关键交互先编写失败测试，再实现页面。专用测试覆盖角色、精确包确认、409、不可信文本、跨项目切换、逐规则证据、normal 拒绝、补证据/阻断、暂停/撤回、查询失败、未知结果和传输契约。

```sh
pnpm test src/pages/Skills.test.tsx src/lib/skills.api.test.ts
pnpm verify
```

`pnpm verify` 包含全量测试、类型检查、lint、格式检查、图标检查、既有自测和构建。真实验收另外需要已认证的 Go 控制面、Python Skill 服务、Neo4j 和登记候选，不能用测试夹具或 mock 页面代替。

本轮服务需在用户可见的 iTerm 中启动，再在可见浏览器中访问 `/cn/skills`。前端单元测试的合成 `PASS` 包仅验证按钮及请求绑定，不是对真实 P2 候选的发布批准。真实候选的审阅挑战与独立任务缺口应继续显示为阻断；`isolated_dev` 也不能代替 P4 的独立验证和效果评估。

## P4 固定三组独立实验

Skill 页下方新增项目级实验区域，独立于当前候选选择，避免新修订实验被旧候选筛选隐藏。实验由宿主先冻结，只提供列表、详情和开始三个入口；浏览器不能上传任务路径、评分报告或模型配置。三组固定为无经验、原始 Memory、提炼 Skill；七个场景共 21 个执行单元。

页面展示实验 ID、manifest 摘要、候选 revision、统一预算、终态进度、H1–H3 修复分母、H4–H7 任务解决数、未知与基础设施无效、全部执行耗时及模型报告费用，并保留逐任务明细。人工边界/规则/严重违规判断仍为 pending，不以已完成或行为通过代替发布批准。费用缺失显示未知，未知项不被静默删除。

`experiments/start` 要求 write；frozen 才提供开始按钮，running 自动轮询详情，查询失败仅刷新查询；completed/interrupted 不隐式重跑。切换项目卸载组件，迟到响应不进入新项目，详情必须与所选实验 ID、候选版本及 manifest 摘要一致。三个入口经同源 Go 会话与项目授权，写请求不自动重试。

新增 `SkillExperiments.test.tsx` 与 API 契约测试覆盖权限、固定身份、一次开始、查询失败、未知/人工待审和中断状态；Go 补充实验路由、严格字段及真实会话代理测试。真实实验结果由主工作区执行并在可见浏览器验收，单元测试数据不构成实验收益证据。
