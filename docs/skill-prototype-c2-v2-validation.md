## 3 验收标准

1. **环境与身份**：真实 CLI 版本与文件摘要匹配；OS 隔离探针通过；候选、导出、套件、资格、政策、模型/工具/预算和采集器均与冻结值一致；首次调用前有批次清单。
2. **校准准入**：none 补丁行为 accepted/passed、采集和过程完整、loading=not_requested、严格整数轮次不超过二、无 budgetExceeded/未复验编辑且政策匹配，才能执行 Skill。否则保留失败和阻断，不追加模型尝试。
3. **Skill 会话**：固定导出加载 verified，满足同样过程和预算条件；初始 scoped 恰两项失败且 Dream 五项健康，最终全部 11 项公开/隐藏通过。所有已观察检查点的 Dream 应保持健康。
4. **真实回读**：schema 5 从两组原生事件、全部公开快照和送达、初始/最终隐藏凭条重算过程和资格；核验批次绑定及 none 结束先于 Skill 开始，不能只信 summary 标志。
5. **完整计划**：自动 planQualified=true 之外，检查原生事件确认初始检查先于编辑、全绿后没有无必要编辑、没有隐藏评测访问或禁止操作。`stopWhenAllChecksPass` 目前是提示约束，不能把它误写成自动门槛已单独证明。
6. **历史与界面**：原 C2 13 份源码/锁、192 份批次文件及旧裁决/挑战不变；新事实追加到 Neo4j，在浏览器展示 schema 5 两组资格、实际过程与分支缺口。当前服务已支持 schema 5，不为导入旧事实重写版本。

记录真实费用、耗时和失败，行为通过、计划合规、规则使用与分支覆盖分栏。完整修复不自动授予分支；失败也不是必须修好之后才能报告的结果。
