## 3 故障注入与恢复约束

不修改旧 Memory 正文、元数据、来源快照或冻结执行器。实际来源不可用演示仅暂挂本实验自建的 Memory 服务子进程；先核对其端点、PID、父进程和身份，finally 与独立恢复保护均负责 SIGCONT。这样保留原服务端点，避免重启随机端口改变服务身份。不得暂停 Neo4j、Qdrant 或用户其他服务。

新服务和批次使用用户 Claude 二进制的私有普通文件副本，目录不含任务/隐藏评测工件。副本已用 --version 和字节比较检查；原二进制不修改。故障注入仅临时移除副本执行权限，扫描得到 unavailable，再恢复原权限/字节；工具依赖的代码指纹在冻结后保持不变。

外部条件恢复不自动清根因。回归前扫描到当前健康/恢复事实，随后新验证回写记录当时的观察水位；只有被裁决合格的新真实验证可用于恢复。不能在故障期间验证，再等条件恢复后将旧验证冒充恢复证明。

## 4 运行预算和失败处理

首发资格为单独的七单元计划；P5 另最多五次真实模型调用：修复 normal 一次、健康 normal 一次、recovery 无 Skill 校准与 Skill 修复各一次、恢复后 normal 修复一次。沿用 Claude Code 2.1.296、固定 claude-opus-5-5、每次 240 秒/12 轮/3 USD、最多两次修复周期；该预算是上限，实际用量由报告记录。

任何超时、规则声明缺失、超周期、隐藏不一致或准入变化按实际结果记录；不能自动重复同一单元直到成功。必要的新批次必须重新登记原因、身份与上限，原运行永久保留。小样本结果仅用于资格与闭环可用性，不证明平均成功率或成本优势。
