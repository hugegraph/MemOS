# P4.1：受信验收器修正、七任务隔离自检与后续资格链路

日期：2026-11-09。基线为 P4 `6f196041`，分支 `codex/skill-prototype-p41`。依据 [P4 实际报告](skill-prototype-p4-results.md) 与 [冻结设计](skill-extraction-design.md)。本文件先提交范围与验收，实际结果随后追加；不改写原 P4 的 21 次运行。

## 1 顺序与交付边界

本轮按用户指定顺序推进：P4.1 验收执行能力 → 人工裁决和分支覆盖证据 → 来源/工具变化、失效传播与新版发布资格 → P5 综合验收。来源/工具演进原属于 P5 工作包，这里将其实现作为进入 P5 综合演示前的准备，不提前宣称演示或发布完成。

P4.1 的完成条件是七个锁定任务的初始故障、reference、unsafe 均通过真实隔离自检，H4 可见检查和最终验收都可用，且凭条能拒绝输入、执行器、环境和结果篡改。H6 的 reference 最高仍为 needs_review。资产自检不是新的独立经验，也不是一次新的 Claude 效果实验。

后续人工裁决必须针对冻结证据包，由真人明确提交。Agent 可整理证据、提出建议和运行检查，不能署名为人类、自动消除未知或凭空确认分支覆盖。当前六规则有 22 个流程分支，七个 transfer holdout 不能证明 MemOS 专用 scoped-read/Dream 修复分支；需要范围内独立验证或经来源支持的新修订，不能靠一次批准补出证据。

## 2 不变性与版本管理

保持原 `skill_adapter/*.py`、`skill_evaluation/` 验收器/任务资产与锁、`skill_experience/evidence.py` 及 P4 实验模块的字节不变。旧适配器摘要覆盖目录中全部 Python 文件，因此新能力放在独立 `memos.skill_verification` 包，而不向旧目录加文件。P4 服务继续回读原冻结清单；新凭条明确使用新的验证器与执行器身份，旧 checker 必须拒绝，不伪装旧摘要。

使用现有 `.venv` 与开发依赖，不同步依赖。保留未跟踪 `bin/`。按文档、实现与测试、实际验证的边界作中文 commit；不推送/合并。凭据、运行工件和部署配置留在宿主私有目录。

## 3 执行设计

采用受信宿主按固定计划启动测试进程，所有执行候选代码的进程继续禁止 fork、禁止网络，候选和控制目录只读。H4 的四个 pytest 顺序由宿主串行编排，每次只能启动一个固定 Python 入口；Agent 无权提交命令、路径、pytest 参数或任意测试内容。这样无需向候选解释器开放派生子进程权限。

H4 保留原合同、任务说明、候选文件政策和判据：调用方合同、状态型 Fake 合同、fixture 单独/组合/倒序行为及 pytest 实际执行审计。新受信 harness 固定 rootdir 和 confcutdir 为本次测试目录；禁止向 `/private` 等祖先目录授予读取权限。原 oracle 与可见脚本保持不变，确定性的新执行计划/有效 harness 单独标识和封存。

最终验收与可见检查共享隔离进程原语。可见检查仅返回原可见材料对应的结果；隐藏测试与 oracle 不进入 Agent 控制目录或可见输出。新 broker 继续快照输入、拒绝修改受保护可见脚本、固定 Unix 请求协议、限制调用数并记录证据。

每个执行有总时限、CPU/文件/输出上限和取消信号。宿主限制固定子运行数量及串行并发；每个候选进程禁 fork，超时、取消、输出溢出或执行失败终止本次进程并保存失败原因。不能把周期性后代扫描描述为硬性进程数限制，也不承诺平台不提供的硬内存隔离。清理只针对本次拥有的进程，不影响用户其他服务。

## 4 新凭条与自检合同

新验证器封存初始/最终快照，继续复用旧文件政策与行为判定逻辑，但以独立 schema/version 和实现摘要绑定以下信息：任务资产、原 oracle、实际执行计划与 harness、隔离政策、每个固定子运行、环境、候选快照、run/attempt、原始结果与归并结果。重评重新核验所有工件及最终补丁，不仅检查 passed 字段或单个 JSON 哈希。H4 的 pytest 审计必须拒绝 skipped、xfail、未实际执行或候选 hook 绕过。

CLI 提供宿主专用七任务隔离自检与单候选验收/凭条检查；输入只能是注册任务、固定 variant 与受信宿主路径。不把 HTTP 请求变成任意代码执行接口。自检目录独占创建，失败保留，不能覆盖或将旧 P4 unknown 升级为 passed。

## 5 人工裁决、覆盖与演进的后续合同

人工复核以追加记录表达，不修改原 Validation/status：绑定原验证、候选/导出、最终补丁、精确规则/分支、事件引用、判据、决定、理由、actor 与审阅包哈希。区分验收基础设施异常、合理停止、真实反例、误用与无关范围。只有具有可信验收与明确人类判断的记录才贡献覆盖；Agent 声明不直接贡献。解除挑战或某一阻断原因不清除其他原因。

来源/工具检查基于实际回读语义摘要及固定能力清单，生成带根因的影响记录。必选固定版本 REQUIRES 反向传播阻断，RELATED_TO 不传播，SUPERSEDES 不重绑定依赖；新版本不自动恢复旧发布。使用准入检查当前资格及依赖闭包，保留旧执行事实与回执。恢复、撤回、重新授权与新版本发布分别记录，真人批准始终绑定完整审阅包。

实现这些能力之前先补具体接口与冲突测试方案。真实候选若仍缺范围内独立证据，则保持不可发布；测试用管理记录必须显式标记，不得作为真实候选发布或实际人类批准。服务启动继续由用户在 iTerm 执行已准备的短命令，界面验证在可见浏览器完成。

### 2026-11-09：实现与本机回归

新增 `memos.skill_verification`，含固定计划、无 fork 执行器、新凭条 checker、可见 broker、七任务自检 CLI 和必须持有当前自检资格的 Claude runner。版本为 `host-fixed-phase-1`、`p41-plan-2`、凭条 schema 3 / validator `p41.1`。H4 的四种 pytest 顺序分别封存实际 setup/call/teardown 记录，宿主复核完整顺序、数量、outcome 与 xfail，再归并验收；退出码不能独自证明执行过检查。

- 新包测试：**104 passed in 38.43s**，含真实 macOS sandbox 七任务三变体、可见 Unix broker、输出/CPU/文件限制、取消/超时清理，以及重新计算外层哈希后仍不能放宽 profile 或删去 pytest 审计的反例。
- 旧 adapter/evaluation/experience/experiments 回归：**544 passed in 101.66s**。
- Ruff 检查、格式检查与 `git diff --check` 通过；未安装或同步依赖。
- 原 P4 manifest 仍为 `9e11b6e293978de61e548367e783159b5c6c0c8e1a7f5d1aacb987e0b1272e1b`，21 次运行及 3 次校准的旧协议凭条复验通过。52 个相关历史文件摘要封存在仓库外，用于正式运行前后比较。

新增 `scripts/dev/skill_p41_console.py`，供 iTerm 运行：先复核历史记录，再独占生成 21 次验收与 14 次可见自检工件，然后用新协议检查三个原 H4 最终补丁，最后运行一次 Claude H4 无经验兼容验证。失败或中断工件保留，已有模型运行不自动重试。它不重启原 P4 服务、不回写原成绩、不发布候选。

单元测试中模拟的 native 事件只用于 runner 编排检查，不算实际 Agent 验证。后续裁决/覆盖/变化传播的具体开发合同见 [P4 后续治理合同](skill-prototype-governance.md)。

用户在新 iTerm 标签页启动专用命令，原 P4 三个服务继续运行。七任务资格为 `a2613b3afb9ef4084ef7d41b060afd7430ca58a653454e9ec9e4811793302863`，21 次隐藏验收得到 14 failed、6 passed、1 needs_review，均符合各锁定变体预期；14 次可见检查的退出码、快照与执行工件也通过复核。H6 reference 保留 needs_review。

三个原 H4 最终补丁在独立新协议下均 passed。这是同一补丁的事后验收兼容性观察，不是新增独立样本或替换原未知分数。前后对比的历史文件摘要与全部 24 个旧协议凭条仍匹配。

随后只执行一次真实 Claude H4 无经验兼容运行：CLI `2.1.296`、模型 `claude-opus-5-5`。Agent 先运行可见检查得到退出码 1，修复 fixture 生命周期后再次检查得到 0；独立五阶段最终验收 passed。106 条事件采集 complete，运行上下文与固定能力匹配，最终补丁凭条匹配。模型报告耗时 31.712 秒、10 turns、费用 `$0.0855502`；费用为模型报告值，不是账单核对。

这次运行不加载 Skill，目的为验证新 broker/执行器真实接通，不能据此声称 Skill 收益、分支覆盖或人工批准。所有工件保存在宿主私有目录，运行报告与凭条摘要另存 `acceptance.json`；没有新增凭据入库、服务重启或自动发布。P4.1 完成，进入 42-A 仍需实现人工裁决及范围内覆盖证据链路。
