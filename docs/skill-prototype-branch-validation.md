# 42-A4 范围内独立任务与分支验证合同

日期：2026-11-09。前置为 [42-A1/A2/A3](skill-prototype-governance.md) 的真实证据登记和人工裁决。本文先定义实现与验收；表中的目标分支不表示已经覆盖。

## 1 这批验证回答什么

冻结候选 `f92905541710def3172d16e9c78d7226bf22e646b4c8baa73da499bf826e2a4c` 有六条规则、22 个分支。原 P4 七任务属于迁移效果实验，不能证明其 MemOS scoped read / Dream UPDATE 专用规则。H4、H6 已经由用户分别确认：任务修复/停止有依据，但范围外规则使用不当。两项决定不贡献覆盖，也不重写原 unknown。

本批问题是：当规则的前提确实出现，Agent 是否执行对应动作、保留真实错误检测能力，并在证据不足时正确退出。范围内通过不证明一般 Python 故障收益，也不补算原实验的成功率。可以出现“任务正确、规则误用”“规则正确停止、问题仍未修复”“候选存在无法观察或互相冲突的分支”等结果。

## 2 执行结果先于覆盖解释

当前 42-A3 的 `repair_confirmed` 要求最终凭条通过且行为文件发生变化；`stop_confirmed` 只覆盖保留行为的停止。不能用它们强行解释所有新任务。42-A4 在引入新任务前扩展版本化结果合同：

| 结果 | 自动事实 | 人工判据 | 修复计数 |
| --- | --- | --- | --- |
| 修复成立 | 初始行为失败、最终独立验收通过、补丁确有行为变化 | 合同未削弱，修复与缺陷相关 | 1 |
| 原本正确 | 初始和最终独立验收通过、行为文件未改 | 识别健康路径且没有无关编辑 | 0 |
| 合理停止且未改行为 | 诊断工件合规、原行为及失败保留 | 说明具体缺口/范围，未猜测合同 | 0 |
| 修复未完成后停止 | 受控执行、最终补丁及残余失败均可核验 | 修改预算未超限，无放宽检测/伪称完成；残余问题明确 | 0 |
| 真实失败/证据不足 | 保留最终失败、工具不可用或不完整记录 | 判断是否为范围内反例或仍需补证据 | 0 |

`exit:success` 是过程结果，不能自动等同于修复数；健康无修改分支需要单独结果。允许判断有限修复后的停止，也不意味着把失败凭条改成通过。新增合同必须带初始/最终验证摘要和任务结果类型；旧 assessment、旧人工决定及旧评分均不可重新解释。每次生成器版本更新由新的 assessment 绑定，已经确认的历史判断留在原事实版本。

## 3 独立资产与隔离实现

新建 `skill_branch_validation` 命名空间与资产锁，任务用途固定为 branch_validation，和 source/dev/原 P4 transfer holdout 分开。任务代码由本批按公开合同独立编写，使用不同数据布局、调用链与反例组合；不能复制 source 的生产切片后仅改变量名。来源审查记录作者方式、依据的合同、与来源代码/补丁的相似部分和独立性局限。共享 API 合同不等于共享案例，但也不能宣称统计意义的随机独立样本。

任务交给 Agent 前固定：任务 ID/revision/lineage、可见合同、初始文件、允许编辑文件、公开检查、隐藏正反例、健康基线、参考解、削弱检测的错误解、评分量表、候选版本、允许贡献的精确分支、工具故障脚本及全部摘要。参考解和错误解仅检验验收器，不成为 Agent 经验或覆盖。

保留旧 `skill_evaluation`、`skill_adapter`、`skill_experiments` 与 P4.1 凭条实现字节。新协议复用 P4.1 固定无 fork 执行器的公开调用，不通过 monkeypatch 把新任务塞进旧 registry，也不让旧 checker 接受新凭条。新增任务编排器、可见 broker 和验收身份显式带新版本，原命令仍按原锁回读。

可见 broker 只接受固定动作。工具故障按预冻结调用序号注入并回传明确不可用结果，不允许 Agent 请求注入/恢复，也不因看见模型失败临时改变脚本。隐藏 oracle 在 Agent 退出后运行。只将公开过程、固定工具事件和脱敏展示写入审阅包，不采集私有推理。

有些分支把“visible checks available”作为前提又包含不可用出口，需要区分进入阶段时可用、执行过程中失去可用性。如果前提始终不成立，任务不能贡献该分支。无法合理观察的分支形成修订反馈，不自动删除或填通过；若最终需要修订候选，应保留本版缺口，再验证新 revision。

## 5 实施顺序与验收

1. **A4a 资产与自检**：先落两个范围内核心任务、健康/错误变体及锁，再扩展组合与边界任务。正确解必须通过，初始缺陷和放宽检测解必须失败；缺合同任务的诊断量表独立检查。自检不调用模型。
2. **A4b 新协议与结果**：固定执行环境、初始/最终凭条、退出类型和工具故障记录。拒绝替换补丁/工具事件/任务锁，限制运行资源。健康通过不能计为修复；受控停止不能覆盖任务失败事实。
3. **A4c Claude 运行与证据接入**：先用 dev 校准新协议，预登记范围内任务清单后运行一次固定 Skill；完整保留失败和成本。新 assessor 通过已注册协议分派，不能浏览器自报验收。
4. **A4d 人工覆盖判断**：每条分支绑定条件观察、实际动作/退出和对应检查。页面显示已覆盖与仍缺项；存在误用、冲突或来源缺口时不得发布。再进入 42-B。

A4a 的完成条件是可信任务资产，而非分支覆盖完成；A4c 的运行完成也不等于 A4d 审阅通过。进入 P5 仍需 [42-A/B 的完整门槛](skill-prototype-governance.md#7-阶段验收与进入-p5-的门槛)。

## 7 A4b 首增量：新凭条协议

`branch-receipt-1` 只用于新 registry 的两个核心任务。它不使用旧 schema/version，也不声称提供新的停止结果类型。先独立完成 `verify_task` / `check_receipt`，再增加 broker、资格检查和 Agent 编排；初始与最终验收各有独立凭条，运行报告将绑定二者。

凭条绑定：固定协议和实现摘要、task ID/revision/digest、run/attempt、候选完整快照、受信 oracle phase、环境、实际执行目录、执行记录及全部工件摘要、文件策略、实际 checks、status、时间和限制。只允许三个状态 passed/failed/error；未执行、缺检查、错导入、进程/资源异常或凭条不匹配均不得 passed。文件政策拒绝新增/删除文件及修改 TASK/公开检查/非允许文件。

回读器以当前固定任务重新构建 phase，通过 P4.1 的通用工件检查器复核实际程序、参数、无 fork/no-network profile 与运行限制；再从保留报告重算状态，不能信任自报通过。替换补丁、篡改执行后重新计算外层摘要、放宽 profile、修改任务锁/协议、缺检查以及跨目录凭条均拒绝。原 P4 和 P4.1 checker 拒绝本协议；本协议也不接受旧凭条。

该凭条只证明受信宿主执行记录和最终文件绑定，不是对抗 Python 同解释器反射的完整安全边界，也不是签名证明。Agent 只能接触独立的公开检查入口；不得得到此 oracle、其文件路径或隐藏验收输出。首增量的完成条件是真实隔离执行和上述反向测试通过，不授予 Skill 发布或模型调用资格。

## 8 A4b 公开检查与运行准入增量

新 `branch-visible-1` broker 只接受 `run_visible_checks`，禁止传程序、路径和任意参数。宿主从新任务锁构建公开检查程序，快照只包含任务文件；隐藏 oracle、参考解和本仓库不在该执行可读范围内。每次调用固定预算与超时，退出必须取消活动检查并回收 socket。记录绑定 task digest、调用序号、候选快照、程序/隔离配置/执行工件、公开输出；回读重新验证所有绑定。公开程序的检查顺序、每项结果与退出码必须一致，空输出或不完整检查不能作为成功。

首版 broker 不注入工具故障；故障场景另建明确版本及预登记脚本，不能对这批运行临时增加故障。工具返回只含公开检查结果及证据索引，不含隐藏验收路径/结果。重放工件不能改变调用结果、文件策略或任务身份。

新资格检查对两个任务分别运行 initial/reference/unsafe 的隐藏凭条和 initial/reference 的公开 broker，即六次隐藏、四次公开检查。固定预期为参考解通过、初始及错误解失败；回读要核验完整矩阵、任务/执行器/broker/verifier 实现摘要、全部凭条和工件。成功摘要本身不是资格，任何缺项、篡改或版本变化都拒绝模型运行。该资格不产生经验、人工批准或分支覆盖。

新 runner 只允许在上述资格当前有效时加载固定候选或无 Skill 做协议校准；复用已验证的 CLI 配置、OS 隔离、hooks、事件与四字段规则记录，不修改旧适配器。显式使用新 registry，绑定初始/最终凭条、事件与固定导出。两题初始须失败，最终通过才可能计修复；加载/采集不完整保持 unknown。运行结束再次核验资格和代码摘要。此增量不声称已经支持健康/停止任务，也不自动登记人工覆盖或发布。

验收顺序：先公开 broker 的实际隔离、资源取消、保护文件和篡改反向测试；再完整资格矩阵与回读反向测试；最后无 Skill 协议校准及两个固定候选任务的真实 Claude 运行。失败的运行完整保存，禁止为取得好结果覆写或重跑并隐藏原尝试。

## 9 A4c 首批真实运行协议

开发脚本 `scripts/dev/skill_branch_console.py` 在已有服务配置中读取受信模型配置，只把不含凭据的固定模型/CLI/预算、任务锁、候选 revision/contentHash/exportHash、运行器与资格摘要写入新的私有批次 manifest。目录必须全新，不覆盖或隐式重跑。批次按顺序最多三次 Agent 运行（每次仍可包含多轮模型请求，由 maxTurns/maxBudgetUsd 限制）：scoped 无 Skill 协议校准、scoped 固定 Skill、Dream 固定 Skill。校准未通过则阻止后两次；正式单元的失败仍保留，并继续收集另一单元。运行结束重新比较固定配置与代码身份。

这不是新一轮三组收益实验。无 Skill 单元只校准新接入，不用于扩大独立样本数；两个正式单元用于观察预登记的六个正常分支，不能支持其余十六个分支，也不证明收益。每次记录初始失败、最终补丁验收、完整加载/采集、公开检查实际送达、规则声明、耗时/成本及失败原因。首批报告保留 `branchCoverage=[]`，须在下一增量经版本化证据接入和人工判断后才可贡献覆盖。

## 10 A4d 首增量：核心任务事实接入与人工分支判断

新事实采用 `schemaVersion=2`、`collectorVersion=branch-review-1`，由新模块负责。旧 `host-review-1` 的 domain、collector、digest 和已保存决定保持不变；仓库只在登记和裁决入口按 schemaVersion 显式分派，未知版本拒绝。管理层的 Validation 仍用已有 actual/independent_task 合同，且导入时 coverage 为空。旧评分与历史裁决不得被新任务覆盖。

新 assessment 保留旧版共同字段，额外绑定 `initialVerification`（status/receiptSha256/protocol/matches/candidateSnapshot）、`publicVerification`（initialExitCode/finalExitCode/recordsVerified/deliveriesVerified/deliveryRefs）、`outcome`、`batchId`、`taskDigest`。deliveryRefs 每项含 checkIndex、startedEvent、completedEvent；引用必须来自本次事件。outcome 只允许 repair_candidate、failed、incomplete：当前仅支持两个初始失败的核心修复题，健康、停止和工具故障任务待单独增量，不能借用旧 stop_confirmed。

自动采集器必须回读：冻结批次、当前协议资格、精确 task/lineage、固定 Skill 控制快照及导出、原生事件完整性、全部公开执行工件及实际送达、初始/最终完整快照和双凭条。初始必须对应锁定 initial 变体；candidateSnapshot 对应最终文件，报告与凭条引用不得逃逸私有根。凭据不进入图或页面，事件展示沿用脱敏投影。只接受批次中的两个 skill 单元；none 校准不登记独立验证。

repair_candidate 要求初始隐藏 failed、初始公开 1、最终隐藏 passed、最终公开 0、行为有变化，并且采集、加载、双凭条、公开工件和送达均完整。否则保留 failed/incomplete 事实，不允许人越过自动事实确认修复。人工判断仍使用原四类 taskDecision，但此版仅允许 repair_confirmed、failed、needs_evidence；确认修复不自动确认规则使用。

每题最多申报 task lock 中对应的三个目标分支。分支需绑定条件观察、动作/退出、检查名称与本次该规则的声明，且确认适用、正确使用、无严重违规；条件与动作不能只有模型声明。未出现的分支仍 missing。两题均通过也最多补六个正常分支，其余十六个及边界覆盖、未决挑战仍阻断发布。

页面展示初始和最终结果、公开检查/送达状态、任务结果分类和批次摘要，解释“候选分支”尚未获得覆盖。沿用现有审阅包/序号/哈希/人工确认事务。真实写入只登记事实；具体裁决在页面准备完毕、用户确认后才提交。

验收：版本分派和旧决定回归；篡改双凭条、初始变体、公开返回、任务/批次身份被拒绝；校准单元禁止登记；自动事实不完整时人工确认修复被拒绝；超出三目标或没有该规则声明的分支被拒绝；真实 Neo4j 登记回读、页面展示与发布继续拒绝。服务由当前终端管理，只重启本任务三个已知进程，不影响 Memory/存储服务。
