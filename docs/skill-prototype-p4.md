# P4：固定三组独立实验与可追溯评分

日期：2026-11-08。依据 [冻结设计第 11 节](skill-extraction-design.md) 和 [P3 验收](skill-prototype-p3.md)。本文先提交范围、契约和验收；实际结果完成后追加。

## 1 范围与完成定义

完成同一冻结来源池下的 **无经验（none）、原始 Memory 经验（raw_memory）、提炼 Skill（skill）** 三组实验。使用 P0b 锁定的七个 holdout，每组每任务一次，合计 21 次正式执行；开发校准、基础设施补跑单列。P3 文档的“手工 Skill”是文字错误，本轮纠正，不能改变冻结比较对象。

交付包括：来源约束的候选修订、历史未知的明确归属、实验清单与完整性门禁、新版隔离运行入口、绑定最终补丁的自动评分、待人工判断的证据包、分层配对报告和浏览器展示。21 次完成指计划的每个单元均有持久终态（通过、失败、未知或有依据的基础设施无效），不要求人为制造全通过或收益。

不自动发布，不用 LLM 或测试通过代替人类对语义、边界和严重违规的判断。不按 holdout 结果修改候选或预算，不将 holdout 回流经验。持续监测、依赖传播和新版本恢复资格属于 P5。当前任务规模仅有七个独立场景，不能宣称统计显著或普遍收益。

## 3 候选修订与历史未知

修订输入仅为原始 MemorySnapshot 对应的冻结 packet、原候选及三个来源审阅问题：补齐 scoped update 的回归与 embedding 失败检查；明确契约与行为均满足时无需修改；将有限修复预算表达为宿主策略，并说明耗尽后的退出。来源没有证明某个固定次数最优，不能把预算策略写成经验事实。

生成请求、父版本、问题清单、模型响应和修订工件摘要均保存；新增向后兼容的修订生成契约，原 P2 工件仍按旧规则验证。新候选产生新 revision，旧正文不改写。当前来源只支持 MemOS 特定合同，任何迁移推断必须显式标为待验证，不能根据 holdout 答案扩展范围。

开发阶段补充：五次重新生成先后遇到输出截断、模型 token 限流与替代模型超时，未得到合格新候选。因此提供明确的 `source_review_patch_v1` 来源约束定点修订证明：原 P2 模型生成证明完整保留；开发者修订只允许上述三个问题涉及的规则/验收字段，每项绑定审阅问题和来源事实，禁止扩大 applicability、替换来源或修改身份。记录 `actor_kind=developer_agent`、`human_approved=false`，不把定点修订伪装成模型响应或真人批准。候选内容仍经过完整结构、引用、流程及前后来源回读检查。正式实验比较的是**模型提炼后经过开发者定点修订的候选**，不能据此宣称纯自动提炼质量已经验证。模型尝试与预算详见[修订开发记录](skill-prototype-p4-revision.md)。

两次修复周期是宿主选择的流程上限提示，仍需审阅其遵循情况；运行器自动强制的是 240 秒、12 轮与 3 USD 上限，不声称已自动识别每个修复周期。

旧 revision 的四次开发执行、三条 unknown 和挑战原样保留。以追加的父子版本关系与修订说明解释旧结果，记录各 unknown 属于连接配置或原生声明契约问题及对应导出版本；不改成成功、不删除、不跨版本充作独立验证。新版本开始新的验证集合，但修订说明必须显式列出未消除的语义或证据风险，不能通过换版本隐匿反例。

## 4 实验清单与分组输入

首次 holdout 前封存不可变 manifest，固定候选/导出、来源水位、原始经验工件、任务资产、CLI 二进制与版本、模型、解释器/适配器/环境、工具、预算、顺序和评分协议。清单摘要为实验身份；任一绑定变化拒绝继续同一实验。重复开始不重复运行；已完成单元不覆盖，进程中断的单元保留 unknown。

初始预算沿用已验证的 dev 设置：每次 240 秒、12 轮、3 USD 上限，一个会话；经验上下文上限为 32768 UTF-8 字节。三组总预算相同，raw 与 Skill 使用相同经验容量上限，实际长度与成本另报。运行前通过 dev 校准核验，若必须调整，只能在首次 holdout 前形成新的清单。计划顺序用固定种子 20261108 在七任务的组内确定，串行执行，不能观察分数后换顺序。

原始经验按 source_id 与 fact_id 固定排序，提供同一 packet 中可公开的来源事实及结果，不总结成过程性规则，不包含候选、holdout 标签、答案或额外检索。超过容量时按固定的完整事实边界截断并记录被选/遗漏 ID。Skill 组只加载固定候选的确定性原生导出。无经验组只得到任务。经验放在只读控制目录，不加入可编辑任务快照。

各组任务文件、工具能力、外部验收和权限边界一致；规则记录工具的可用性需统一，空规则组不能借此取得额外经验。明确区分经验被提供、被读取和声明使用。上下文记录与所有组工具集合须真实核验。

## 5 新运行入口与隔离

新增 `memos.skill_experiments`，仅接受宿主注册的冻结实验，不能经 HTTP 上传任意任务、路径、脚本或评分报告。新运行器允许经过 manifest 核验的 holdout，继续使用 macOS OS 隔离、只读控制目录、可见检查代理和外部 verifier；拒绝读取仓库、隐藏 oracle、其他组工件和私有配置。原 P1 运行器继续拒绝 holdout。

每次保存 session/run/attempt、完整事件、初始/最终快照、原生结果、receipt 与 SHA、加载与采集状态、消耗和安全错误。评分再次核对 receipt 与当前最终补丁及任务清单，不能只信进程退出码。失败不自动换会话重试；只有可证实的调用前基础设施失败可原配置补跑一次，原记录保留。Agent 超时、预算耗尽、错误修改及采集不足仍在分母，不能冒充基础设施故障。

## 6 评分与结论

自动评分：外部行为通过、补丁绑定、文件政策、证据完整性、加载状态、耗时、模型报告费用、工具调用数。H1–H3 单列主修复率；H4–H7 单列任务是否解决与边界判断。unknown 在保守修复率中按未通过处理，完整配对数和基础设施无效数单列。费用缺失记未知，不推算账单。

人工项 `boundary_pass`、`branch_supported`、`critical_violation` 保持 null/pending，附固定量表、观察和工件引用，除非获得明确人类审阅。自动识别的文件政策违规可单独阻断，但不能由字符串匹配宣称理解了语义。规则声明不自动产生独立分支覆盖。H6 合理停止不计修复成功。

报告包含 21 单元明细、每任务三组配对、H1–H3 与 H4–H7 分层汇总、所有执行与成功子集耗时/成本、失败/未知/补跑和限制。若均通过，明确本次未观察到功能差异；若 Skill 无收益或退化，原样报告。正式人工发布仍经 P3 精确审阅包，未决判断不能被实验完成状态清除。

## 8 实际结果

### 8.1 工程与候选准备

Python 相关回归（P0–P4、既有 API/Dream 相关路径）**872 passed in 91.45s**，包含 19 项真实独立 Neo4j 测试。最后补充修订记录冻结与候选来源提示后，manifest/controller 专项再次 **15 passed**。Go `make check` 全部通过；前端 `pnpm verify` 为 **145 passed / 28 files**，类型、lint、格式、契约自测和构建通过。受保护的旧适配器、证据核心、任务资产与 Python 依赖未改动。

五次真实开发生成均未形成候选，分别为两次输出截断、两次未取得响应的 provider 错误、一次替代模型超时；独立连接探针确认旧模型存在 HTTP 429 token 限流。原始失败、模型身份与已报告用量保存，不将限流和截断混作同一原因。详见[开发生成记录](skill-prototype-p4-revision.md)。

随后由未接收评测规格的独立来源作者提出明确字段补丁，并使用 `source_review_patch_v1` 在真实 Memory 前后回读后封存。候选 revision 为 `f92905541710def3172d16e9c78d7226bf22e646b4c8baa73da499bf826e2a4c`；6 条规则，原 25 条引用全部保留并新增 2 条，合计 27 条；四种出口与原适用范围保留。原生正文为 11979 UTF-8 字节，未超过统一 32768 字节容量。修订记录 `e028f2c2502811544318ddf8e26ab046b3343b25be8fb223076cea92497caec4` 绑定父版本、22 个字段替换、来源反馈和原四次开发运行的归属；`human_approved=false`。

历史记录仍属于旧 revision：三次 unknown 保留其连接/声明采集问题，最新 v3 成功也不消除它们；这些记录不会成为新版本的独立验证。新候选的健康流程、语义正确性与迁移能力继续待验证，不因结构和出处核查通过而宣称可发布。

### 8.2 可见执行方式

`scripts/dev/skill_p4_console.py --config <私有控制台配置>` 先执行三组 dev 校准，再封存 manifest 并接续 P3 的服务控制台。控制台配置在 P3 字段之外增加 `preparation`，包含 `candidate/calibration/experiment` 三个宿主绝对路径；不接受 HTTP 传入。校准失败或中断不会自动重跑，已有成功校准复用其精确凭条并在冻结时复验。正式实验必须在已认证浏览器中显式开始。

新运行器支持取消信号，服务关闭时终止本次模型进程及其后代，保存 partial 记录和最终快照；中断恢复区分已执行未知与未启动单元，不虚报完成 21 次。批次中的费用、耗时和失败记录不会因结束复核或图写入失败被抹去。评分和执行实现摘要均纳入冻结身份。
