- 已安装三个项目的 `.claude/settings.local.json`，各追加 8 类事件。全局 Claude settings 的 SHA-256 与安装前一致；项目私有配置和备份均被本地 Git 排除。
- 已配置 macOS 用户级 LaunchAgent，当前处于运行状态。只读状态页面为 `http://127.0.0.1:5282/`，浏览器已展示真实记录及展开的经验内容。
- MemOS、MemOS-be、MemOS-fe 的原生 Claude CLI 会话均自动产生 Hook 事件。验证使用 CLI 的 `-p` 模式和项目原生配置，不使用原受控执行器的临时 Hook 配置；没有测试交互 TUI 的所有操作。
- 正常 Read 和文件不存在的失败 Read 均被记录；范围外会话成功执行，但没有进入采集账本。
- 最终干净验证会话完成 Read → 最终回复 → 本地归档 → Memory 写入与回读。原始用户请求没有额外启动脚本文本。
- 最终共 5 个范围内会话、29 条事件、6 份经验修订，全部回读确认，共关联 7 个 Memory ID。6 份修订不代表 6 个独立成功任务：包含未登录失败会话及其完整性修订。
- 在队列同步后，向本服务发送 SIGTERM，LaunchAgent 自动启动新进程；验证时 23 条既有事件和经验身份均保留。之后完成最终会话，累计 29 条事件。
- 26 项新增测试通过；与 Memory 客户端和原 MemoryBridge 合计 82 项回归通过。Ruff、格式检查、Git diff 检查及提交钩子通过。

## 真实验证中的问题与处理

1. 首次直接启动默认 Claude 返回 `Not logged in`，没有执行工具。该失败及缺最终回复状态保留。后续验证仅给验证进程提供已有原型的模型连接环境，并显式选择原型模型；没有修改用户全局登录配置。用户正常使用仍需有效的 Claude 登录或自己的模型连接配置。
2. Memory fast 模式对较长内容分块，保留完整来源的方式不同于旧受控证据合同。新的日常采集核验支持完整来源与正文片段并存，回读标注 `source_identity_only`，不赋予语义正确或修复成功资格。首次不匹配记录保留在投递审计中；修正后只重新读取原 Memory，未重新 POST。
3. 验证进程曾继承 Python 启动脚本的 stdin，使额外脚本成为实际提示的一部分。采集器正确保留了实际输入；这些运行不作为效果实验。最终验证明确使用 `stdin=DEVNULL`，重新完成干净会话，保留旧记录。
4. 状态页首次导航被跨站读取防护误挡，已区分正常顶层导航与跨源脚本读取；仍拒绝不匹配的 Host、跨源脚本读取和写请求。

五次成功完成的 CLI 验证（包括一个范围外对照）报告费用合计约 0.284 美元；首次未登录报告费用为零。这是连接与采集验证成本，不是 Skill 效果或成本收益实验。

## 使用与限制

在任一已授权项目中重新启动 Claude Code，照常执行任务即可。后台不依赖浏览器或本次助手会话；状态页手动刷新显示新记录。完整安装、停用、日志及只读回读命令见 [操作文档](skill-prototype-daily-capture.md)。

当前自动化止于“日常事件 → 待核验经验 → 现有 Memory”。不自动提炼或发布 Skill，不自动加载固定任务的 Dream Skill，不把模型自报当作独立验收。后续需要为日常经验补齐真实项目验收、相关经验发现与候选触发，以及通用会话的固定版本加载契约。

首版采集用户请求、工具输入/输出/错误和每轮最终回复；不读取历史 transcript，不采集内部推理，不保证覆盖所有中间自然语言消息、子 Agent 或用户取消行为。模式与已知值脱敏不能识别全部语义隐私；超长内容有界截断。SQLite 达 512 MiB 后拒绝继续写入并报告安全错误；保留策略、长期归档、自动清理与后台远程部署尚未实现。工具证据为观察，未包含可授予修复成功资格的独立最终补丁验收。
