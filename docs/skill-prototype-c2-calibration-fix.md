# C2 实跑偏差与校准准入修正合同

日期：2026-11-09。基于 C2 实现 `8b07fa2e`。本补充先于修正代码提交，不改变原 C2 开发合同、原运行和原评分。

## 1 实际发现

固定批次 `13000cb801c9…` 的 none 和 Skill 最终公开及隐藏检查均通过。none 的实际检查点轮次为 0→1→2→3，超过 C2 合同规定的每会话两轮；原 batch 只检查 `status == passed`，因此错误地准入第二个 Skill 会话并将 summary.success 写为 true。none 没有收到两轮定义的可见提示，这是宿主协议缺口，不是 none 的 Skill 误用。

原报告中 passed 仍准确表示补丁行为，不能改成行为失败。原 summary、源码、两份报告、凭条和 schema 4 事实全部保留；当前批次不能被描述为完整合规通过。新增审计明确标记计划偏差，不靠重跑覆盖这份记录。

单次 Skill 会话一轮修复、两次检查，Dream 初始和最终健康。两项验证分支有可审阅的过程依据，但 confirm_contract#3 声明时序不满足，repair_scoped_reads#0 没有声明；仍不自动授予覆盖。校准准入偏差与单次修复正确性分开记录。

## 2 修正范围

不改已经绑定真实工件的 C2 原模块。新增版本化 runner、batch 和 collector/治理入口，沿用 C2 的任务、锁、公开/隐藏验收和过程计数。新执行器 `c2-claude-2` 对 none/Skill 加入相同的可见宿主预算说明：每个公开检查之间的 Edit/Write 尝试批次计一轮，最多两轮，全量检查通过后停止无必要编辑，无法完成则如实停止。提示不包含目标分支或答案。

新 `c2-batch-2` 将行为结果与执行计划资格分开：原 status/taskAccepted 语义不变，新增 planQualified/planIssues。只有 none 的行为通过、采集与过程完整、组对应加载状态正确、严格整数轮次不超过二、无预算超限、无末尾未复验编辑，才能启动 Skill。Skill 也必须满足相同计划条件，整批才能通过。损坏、缺字段、bool 伪装整数及状态矛盾均不准入。

CLI `maxTurns=12` 表示传入固定 CLI 的限制参数；原生 num_turns 在本次分别为 14/13。两者计数语义尚未证实相同，不用其中一个替代宿主编辑轮次，也不声称实际原生计数≤12。保留原值与 CLI 结果；后续适配器调研需解释该差异。

## 3 回读与治理

新增事实版本 schema 5 / `c2-review-2`，保留 schema 4。新 collector 必须重新核验校准会话的原生上下文、事件、全部公开快照和送达、初始/最终隐藏凭条及过程计数，不能只相信 none 报告的 budgetExceeded 或新 summary 标志。计划资格绑定两份报告、固定清单和当前 Skill 事实；跨批次、重算外层摘要后的伪轮次或错误组不能准入。

具体绑定：清单新增每批固定的 batchNonce，身份复验始终复用该值。runId 编入完整批次摘要、组名和随机后缀，在既有 80 字符限制内让原生事件与凭条自身关联批次；校准的原生结束必须早于 Skill 开始。不能只校验可独立改写的 report.experiment_id。

治理在单次修复判断之外增加计划资格约束：未满足计划时可保留任务结果、失败和合理使用的人工分析，但不能计入本批次的分支覆盖或发布准入。原 schema 4 producer 和五条旧裁决不变。页面明确展示校准/当前会话的计划资格与原因，不能把最终绿灯等同批次合规。

## 4 验收及本轮边界

先补“none 行为通过但三轮”的失败测试，再实现硬门槛；断言 Skill runner 不被调用且原 none 行为仍 passed。补缺字段、假整数、不完整过程、末尾编辑、Skill 超限及 CLI/模型身份变动等负例。通过真实隔离器的合成原生链验证新提示对称、固定导出、两会话回读和 schema 5 图事务；这些合成记录不算真实模型经历。

对已经完成的原 C2 批次追加只读审计，证明新判据会拒绝其计划资格，并核验原工件哈希不变。完成前端完整检查、真实 schema 4 事实浏览器展示及旧协议回归。本轮已运行的两次模型会话不追加、不替换；新执行协议的真实模型复验保留为明确缺口，需在后续单独冻结批次。不能将代码/回放检查通过写成新协议已经真实 Claude 验证通过。
