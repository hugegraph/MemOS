# 验收契约与公开复现入口开发计划

日期：2026-11-11。基于本机 U1–U4 分支，新建 `codex/skill-contract-repro-v1`。本轮限于 Dream UPDATE 已有场景；不扩大 Release、不改写历史批次、不自动发布。

## U5：检查契约与现有实验审阅

把已发布 Skill 的验收拆成可逐项核对的语义义务。登记当前 P5 与两个 transfer 任务的检查来源、可见性、覆盖和缺口；名称相似不构成等价。登记绑定任务/验收器摘要，未知或发生变化的实现拒绝使用旧映射。自动结果只说明证据充分性，不替代规则使用的人工判断。

提供只读审计命令：回读固定 transfer 批次、最终补丁收据、原生检查交付和规则声明，输出独立新工件。区分最终行为通过、Agent 可见证据、完整验收资格；隐藏检查不能补作 Agent 已执行的公开验证。已有两次 Skill 执行追加受托语义审阅记录，逐条引用原生事件；不更改原 `unreviewed` 字段、不追授覆盖。

验收：正确 P5 检查清单可覆盖既定义务；transfer 的单项公开检查不能变为完整通过；缺项、失败、重复项、未知名称、错误摘要和篡改回执均不能取得完整资格。审阅结果保持 publicationEvidence=false、branchCoverage=[]。原六单元清单、结果和工件摘要不变。

## U6：公开复现入口

新增独立 `skill_demo` 宿主入口与公开配置模板，复用现有受控任务、证据封存、MemoryBridge、候选提炼和图谱导入。提供环境检查、不调用模型的隔离自检，以及在全新输出目录中执行来源收集、Memory 入库回读、固定来源计划、候选提炼、图谱导入和追溯的分阶段命令。来源集合固定为已有 Dream 与 scoped 两个来源谱系；后者用于范围对照，不声称增加 Dream 修复经验。

凭据从环境变量取得；不复制本机私有来源包或账户配置到仓库。来源失败和不确定结果保留，不自动重新调用模型；Memory 未确认时仅沿原账本核对，不重复 POST。候选仍需语义修订、独立验证及人工发布，不能把演示生成的候选当作已发布 c7 版本。操作指南连接现有管理界面与 P5 发布/失效恢复流程，并明确人工关口和已验证边界。

验收：新目录能不依赖旧候选/旧 Memory 账本建立自己的来源与候选；完整来源集合缺失时阻断提炼；错误配置、已有输出、重复模型阶段和服务异常安全失败且保留已完成工件。公开自检无需模型、Memory 或 Neo4j；在线路径使用真实 Claude、真实 Memory 回读与独立 Neo4j 项目验证。模型生成失败是有效失败记录，不以模板伪装提炼成功。

## 实施与提交

先为映射与阶段边界写失败测试，再实现；冻结的 adapter、transfer、P5 和已发布候选不就地修改。新增模块不改变正常管理服务，保持既有服务可用。完成定向 Python 检查、离线自检和在线复现后，写结果与已知限制，分包中文提交。本轮不引入分布式调度、多 Agent、新问题族或协议大重构。
